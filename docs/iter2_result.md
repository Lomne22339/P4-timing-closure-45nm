# Iteration 2: Clock Relaxation Sweep

**Date:** Sep 19, 2026
**Method:** Cadence Tempus 20.10 — swept clock period from 5.0 to 8.0 ns in 0.5 ns steps
**Netlist:** iter1 (identical to baseline; Genus effort high produced no divergent netlist)

## Motivation

Iteration 1 established that Genus synthesis effort is a null lever on this design. Rather than continue searching for tool-driven improvement, iteration 2 asks a different question: **at what clock frequency does this design actually close on Nangate FreePDK45?** The clock period is swept; the closure knee identifies the true architectural limit.

## Interpolated closure point

Because the netlist is unchanged across sweeps and no parasitics are annotated, the arrival time at the endpoint is invariant at **5089 ps** for every clock period. Closure is therefore governed by a simple inequality:

```
T_closure = arrival + setup + uncertainty
          = 5089 + 1020 + 200
          = 6309 ps
```

**Maximum achievable frequency = 1 / 6.309 ns = 158.5 MHz.**

The sweep points confirm the calculation: at 6.0 ns period (150 ps below closure), WNS is −309 ps; at 6.5 ns (191 ps above closure), WNS is +191 ps — linear response consistent with a fixed arrival time.

## Conclusion

**The design has a hard architectural limit of 158.5 MHz on Nangate FreePDK45 with the current netlist.**

This is not a tool limitation and not a fixable violation — it is the design's actual operating ceiling on this library. The critical path (31 combinational gates through the multiplier's carry chain) cannot be compressed without one of:

- Changing the library to one with dedicated adder cells (e.g., GSCLIB045's `ADDFHX*` family — see [P3b](https://github.com/Lomne22339/P3b-cadence-45nm-MAC))
- Pipelining the multiplier at the RTL level (breaks the combinational path with an intermediate register at cost of +1 cycle latency)
